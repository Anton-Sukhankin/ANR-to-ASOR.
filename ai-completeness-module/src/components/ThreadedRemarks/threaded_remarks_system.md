# Компонент: Тред-система замечаний (Threaded Remarks)
`S.Cost / src / components / ThreadedRemarks / threaded_remarks_system.md`

## 1. Назначение компонента
Компонент заменяет хаотичную линейную переписку (комментарии в Excel, письма в Outlook) на централизованное обсуждение замечаний внутри интерфейса S.Cost. Это обеспечивает прозрачную коммуникацию между подрядчиками («кожаными сметчиками») и проверяющими, а также сохраняет структурированную историю споров (legacy) для обучения ИИ.

---

## 2. Модель взаимодействия и логика (GitLab MR Style)

1. **Создание замечания:** 
   * Подрядчик или сметчик может выделить конкретную строку сметы или загруженный файл и нажать «Добавить замечание».
   * Это действие создает **Тред (Thread / Цепочку обсуждения)**.
2. **Ведение диалога:**
   * Все последующие ответы участников по данному замечанию пишутся строго внутрь этого треда (в виде вложенного дерева сообщений).
3. **Резолв замечаний (Resolve Status):**
   * Каждый тред имеет статус `[ ] Решено` (Resolve / Unresolve).
   * **Бизнес-блокировка:** Система не позволяет перевести документ на следующий этап согласования (например, отправить на создание договора), если в документе остался хотя бы один тред в статусе `Не решено`.

---

## 3. Схема визуального рендеринга треда в интерфейсе

```
+--------------------------------------------------------------------------+
|  Строка сметы №1124: "Разработка грунта механизированным способом"      |
+--------------------------------------------------------------------------+
|   [!] Тред #1 (Открыт): Превышение сметной стоимости на 14%              |
|   |                                                                      |
|   +-- [Подрядчик] Сидоров И.И. (12.05 14:20):                             |
|   |   "Объем грунта увеличен из-за просадки фундамента, вот скан акта."   |
|   |   📎 Акт_осмотра_грунта.pdf                                           |
|   |                                                                      |
|   +-- [Сметчик] Мустафаева Э.С. (12.05 15:10):                            |
|       "Акт принят. Корректируйте расценки во 2 столбце."                 |
|                                                                          |
|   [ Ответить в тред... ]                 [x Отметить тред как решенный]  |
+--------------------------------------------------------------------------+
```

## 4. Контракт данных: Схема треда замечаний (State Schema)

Массив тредов замечаний, привязанный к документу, выглядит следующим образом:

```json
[
  {
    "thread_id": "string (UUID треда)",
    "target": {
      "type": "row | file",
      "id": "string (ID строки сметы или ID файла)"
    },
    "is_resolved": "boolean (статус решения)",
    "resolved_by": "string (имя пользователя, закрывшего тред | null)",
    "resolved_at": "string (ISO дата закрытия | null)",
    "messages": [
      {
        "message_id": "string (UUID сообщения)",
        "author": {
          "name": "string (Имя автора)",
          "role": "string (сметчик | подрядчик | супер-сметчик)"
        },
        "sent_at": "string (ISO дата отправки)",
        "text": "string (текст сообщения с поддержкой ссылок)",
        "attachment": {
          "name": "string (имя вложенного файла | null)",
          "url": "string (ссылка на файл | null)"
        }
      }
    ]
  }
]
```

### 5. Интеграция с «ИИ-сменщиком»
Вся история тредов в формате JSON сохраняется в базе данных проекта. ИИ-ассистент считывает эти массивы, чтобы:
1. Выдавать подсказки по разрешению споров (например, считывая аргументы Сидорова, ИИ может автоматически найти нужный ГОСТ в ТДУ и подтвердить правоту подрядчика).
2. Анализировать повторяющиеся ошибки подрядчиков для формирования сводного отчета Gate Keeper.

## 6. Связь с программным кодом (API & DOM Спецификация)

Для обеспечения связи технического описания с кодом на этапе разработки (Шаг 4.5) зафиксированы следующие ориентировочные DOM-точки привязки и структуры данных:

### 6.1. DOM-селекторы и Точки монтирования
* **Привязка к табличным строкам:** Каждая строка сметы (например, `#row-1124`) или файла дерева вложений будет иметь выделенный контейнер замечаний `.remarks-thread-container` для вывода GitLab-like MR цепочек.
* **Кнопка создания замечания:** `.btn-add-remark` — вызывает форму открытия нового обсуждения.
* **Чекбокс резолва:** `.btn-resolve-thread` — переводит статус треда в закрытый.
