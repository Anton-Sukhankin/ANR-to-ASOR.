# Компонент: Вкладка «ИИ-Анализ комплектности»
`S.Cost / src / components / AICompletenessTab / ai_completeness_tab.md`

## 1. Назначение компонента
Вкладка «ИИ-Анализ комплектности» является ключевым рабочим столом супер-сметчика для контроля полноты и целостности пакета документов. Она интегрируется в основную страницу работы с документами в качестве второй вкладки рядом со стандартной загрузкой.

---

## 1.5. Интеграция с главным списком: «Общий ИИ-статус документа»
Перед тем как пользователь перейдет во Вкладку 2 («ИИ-Анализ»), статус обработки пакета документов должен отображаться в **главной таблице загруженных документов** (которая представлена на исходном референсе).

В главную таблицу добавляется новый столбец **«ИИ-статус» (ИИ-комплектность)**:

### Жизненный цикл и состояния общего ИИ-статуса документа:

Детальное описание бизнес-логики, Hex-кодов и правил перехода этих статусов вынесено в единый источник истины дизайн-системы:

## 2. Архитектура размещения (Segment-control и вкладочная сетка)
Переключение между режимами `Загруженные документы` и `ИИ-Анализ комплектности` размещается не в отдельной глобальной полосе под шапкой, а внутри основной рабочей области как компактный segment-control. Control выровнен по левому краю и расположен над сводными карточками статистики пакета документов. Ниже карточек отображается область, где во вкладке ИИ-Анализа находятся виджет `Структура вложений` и правая панель метаданных.

Иконка сегмента `ИИ-Анализ комплектности` использует SVG-метафору искусственного интеллекта в виде звездочек. Размер иконки остается `15x15 px`, цвет наследуется от `.tab-icon` и становится синим в активном/hover-состоянии segment-control.

При переходе на вкладку вся рабочая область страницы перестраивается под аналитический дашборд.

```
+--------------------------------------------------------------------------------+
|  [ Стандартный реестр ] [ RAG-Анализ ИИ / ИИ-Анализ комплектности ]             |
+--------------------------------------------------------------------------------+
|  [ Общий статус РВЕ: title, description ]                                      |
|  [ Требования ] [ Комплектность ] [ Документы / Предупр. ] [ Обработка / Ошибки ] [ Профиль ] |
+--------------------------------------------------------------------------------+
|  [ Дерево вложений и РАГ-статусы ]      |  [ Панель метаданных и сопоставления]|

```

## 3. Функциональные элементы и логика работы

### 3.1. Верхний аналитический блок РВЕ
* **Описание:** Расположен между segment-control и `.ai-split-layout`, вне компонента `Структура вложений`.
* **Состав:** Единый блок `rve-dashboard-card`: сверху общий статус РВЕ, снизу семь сводных ячеек `Требования`, `Комплектность`, `Документы`, `В обработке`, `Предупреждения`, `Ошибки`, `Профиль проверки`.
* **Визуальная модель:** Общий статус содержит интерактивную статусную подложку, title и description без технических API-тегов. При hover на верхний статусный блок или focus на подложку вместо статусной метафоры появляется стрелка раскрытия или сворачивания; нижний блок сводной статистики не запускает эту индикацию. Сводные ячейки по умолчанию свернуты, плавно раскрываются кликом по любой точке верхнего статусного блока и работают как одна табличная строка с правыми вертикальными разделителями на всю высоту нижнего блока, чтобы пользователь мог быстро считать критичные числа без перехода в дерево.
* **Данные:** Значения рассчитываются из текущего дерева вложений и обновляются при перерисовке дерева, пересчете статусов и изменении фильтров.
* **UX-роль:** Блок является общей сводкой вкладки, а не частью хедера дерева. Поэтому рядом с title `Структура вложений` не отображается индикация раскрытия/сворачивания статистики.

### 3.2. Виджет общего статуса «Gate Keeper»
* **Описание:** Расположен горизонтально в самом верху вкладки. Показывает итоговое заключение ИИ.
* **Логика состояний:**
  * **Зеленый (Комплект собран):** Все обязательные документы распознаны, перекрестные ссылки верны.
  * **Красный (Некомплект):** Обнаружен дефицит документов. Рядом выводится список недостающих сущностей.
* **Элементы управления:** Кнопка **«Пересчитать статус»** для принудительного повторного запуска проверки комплектности по всему пакету.

### 3.3. Навигационный Алерт (Критическое предупреждение)
* **Поведение:** Автоматически всплывает при первом переходе на вкладку, если общий статус «Gate Keeper» равен `Ошибка / Красный`.
* **Визуальные требования:**
  * Яркая подложка с мягким красным градиентом.
  * Текст ошибки: *«Внимание! Обнаружены критические несоответствия по мнению ИИ. Проверьте связи вложений»*.
  * Кнопка-ссылка *«Подробнее»* (автоматически фокусирует внимание пользователя на строке первого ошибочного файла в дереве вложений).

### 3.4. Разделение экрана на две секции (Split Screen Layout)
* **Левая секция (60% ширины по умолчанию):** Занимает компонент дерева вложений (File Tree) со статусами.
* **Правая секция (40% ширины по умолчанию):** Динамическая боковая панель метаданных (Metadata Mapping Panel), а также интерфейсы, которые временно открываются на ее месте: фильтрация и технические параметры pipeline.
  * При клике на любой узел в левом дереве правая панель плавно обновляет информацию, показывая тип файла, исходный тип, тип по классификации ИИ, оценку уверенности сети и технические характеристики.
* **Разделитель между секциями:** между левой и правой панелью находится интерактивная зона `split-resize-handle` шириной 16 px.
  * При наведении курсор меняется на `col-resize`, показывая возможность изменения ширины.
  * Drag влево/вправо меняет ширину дерева и правой рабочей области без перезагрузки страницы.
  * Двойной клик, `Enter` или `Home` возвращают раскладку к исходному состоянию 60/40.
  * На узких экранах, где split превращается в одну колонку, разделитель скрывается.

### 3.5. Блок Супер-Администратора
* Отображается **только** для пользователей с системной ролью `Super Admin`.
* Содержит:
  * Текстовую метрику выполнения пайплайна: `Время обработки: 14.2 сек`.
  * Интерактивную ссылку `[Логи РАГ-пайплайна]`, перенаправляющую администратора на консоль отладки бэкенда.

## 4. Связь с программным кодом (API & DOM Спецификация)

Для обеспечения бесшовной связи технического описания с реальной реализацией ниже приведены ключевые программные идентификаторы, DOM-точки монтирования и прямые интерактивные ссылки на исходный код:

### 4.1. DOM-селекторы и Точки монтирования
* **Общая область вкладки:** `#pane-ai` — контейнер аналитического дашборда.
* **Стандартная загрузка:** `#pane-standard` — контейнер базовой вкладки.
* **Segment-control вкладок:** `.scost-tabs-navigation` — компактный переключатель режимов внутри `main.scost-main-content`.
* **Рабочая область вкладок:** `.scost-tab-stage` — контейнер, внутри которого располагаются `#pane-standard` и `#pane-ai`.
* **Верхняя аналитическая зона:** `#tree-summary-cards-root` — контейнер над `.ai-split-layout`, который содержит единый блок `rve-dashboard-card`: общий статус РВЕ сверху и семь сводных ячеек снизу. Нижняя сводная строка управляется кнопкой `#rve-summary-toggle` внутри статусной подложки.
* **Общий статус РВЕ:** `.overall-status-card` — динамическая карточка итогового вердикта проверки. Отображает состояния `Allowed` / `Done`, `Processing`, `Manual Review` или `Blocked` и объясняет результат проверки через title и description без технических тегов и прямых действий внутри самой карточки.
* **Верхний баннер алертов:** `#completeness-alert-banner` — плашка предупреждений.
* **Итоговое заключение:** `#gk-verdict-text` — текстовый элемент статуса Gate Keeper.
* **Кнопка пересчета:** `#btn-recalc-status` — кнопка запуска симуляции в Gate Keeper.
* **Кнопка баннера:** `#btn-focus-error` — кнопка перехода к ошибке в дереве.

### 4.2. Глобальное JS API (window)
* **Запуск презентационной вкладки 1:** `window.initStandardUploadTab()` — монтирует стандартный список файлов.
* **Переключение вкладок:** `window.switchTab(tabName)` — управляет переключением вкладочных панелей (`standard` / `ai`).
* **Защита переключения вкладок:** `app.js` регистрирует обработчики вкладок до отложенного открытия технических режимов правой панели. Ошибка в диагностическом интерфейсе метаданных не должна блокировать переход на вкладку «ИИ-Анализ комплектности».
* **Маршрутизация правой панели:** при выборе файла `app.js` сохраняет активный режим правой панели. Если открыт технический режим pipeline, выбор другого файла обновляет технические параметры этого файла, а не возвращает панель к обычной карточке метаданных.
