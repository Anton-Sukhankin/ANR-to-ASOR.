# Компонент: Масштабируемый боковой чат с ИИ (AI Sidebar Drawer)
Область: демонстрационный чат самостоятельного пакета комплектности, не переносимый чат основного проекта. Документ нужен при изменении этого компонента; браузерные функции `window.*` не являются серверным API. Интегрированный дровер описан в [спецификации проекта](../../../../docs/07-check-workspace-target.md).

## 1. Назначение компонента
Чат является интерактивным сквозным ассистентом, помогающим сметчику анализировать данные на текущей странице, выполнять рутинные действия по текстовым командам и передавать управляющие сигналы ИИ-модели.

---

## 2. Поведение интерфейса (UX/UI Спецификации)

### 2.1. Форм-фактор и Масштабирование
* **Тип:** Выдвижной правый дровер (Right Drawer), перекрывающий основную сетку страницы или плавно сдвигающий ее влево.
* **Ширина по умолчанию:** 970px при первичном открытии чата; значение закреплено в CSS-переменной `--ai-drawer-default-width`.
* **Масштабирование (Resize):** Левая граница дровера имеет интерактивную зону захвата (Resize Handle) шириной 6px. Пользователь может перетаскивать границу мышкой для регулирования ширины чата в диапазоне от **670px** до **1270px**.
* **Скролл:** Область сообщений имеет выделенный независимый вертикальный скролл.
* **Закрытие по внешнему клику:** если дровер открыт, клик по любой области страницы вне `#ai-drawer` закрывает чат. Клик по плавающей кнопке `#btn-trigger-ai-chat` не считается внешним закрытием, чтобы кнопка продолжала работать как toggle.
* **Демо-видимость триггера:** в текущей демонстрационной конфигурации плавающая кнопка `#btn-trigger-ai-chat` остается в DOM и сохраняет JS-обработчик, но визуально скрыта через `opacity: 0`, `visibility: hidden`, `pointer-events: none`, `aria-hidden="true"` и `tabindex="-1"`. Это сохраняет возможность быстро вернуть индикатор без восстановления логики чата.
* **Контекстная доступность:** если плавающий триггер будет снова показан, он должен скрываться, когда правая область занята панелью фильтрации документов. Это предотвращает конкуренцию двух задач: настройки фильтров и диалога с ИИ.
* **Плавающая метафора ИИ:** если триггер снова включается в интерфейс, внутри кнопки используется та же SVG-иконка со звездочками, что и в шапке чата, но в белом цвете и размере `32x32px`. Иконка центрируется внутри круглой кнопки через flex-выравнивание самой кнопки и внутреннего `span.ai-icon`. Цветная emoji-иконка и градиент внутри метафоры не применяются, чтобы знак оставался монохромным на синей кнопке.

### 2.2. Шапка дровера
* **Левая метафора ИИ:** в шапке используется такая же подложка, как у аватарки ИИ-сметчика в ленте сообщений: `36x36px`, светло-голубой фон, `border-radius: 8px`.
* **Иконка внутри подложки:** метафора искусственного интеллекта в виде SVG-звездочек сохраняется и отображается размером `22x22px` в синем цвете.
* **Заголовок:** текст `ИИ-Сметчик S.Cost` расположен справа от иконки; кнопка закрытия остается в правой части шапки.
* **Дескрипшен контекста:** под заголовком выводится текущий рабочий контекст чата, например `Контекст: ИИ-анализ комплектности · Задание на АСОР Бриз Корпус 19`. Отдельная контекстная полоска под шапкой не используется.
* **Обновление контекста:** при открытии чата вызывается `window.updateAIDrawerContext()`, который обновляет текст `#chat-context-text` по текущему состоянию интерфейса.

### 2.3. Контекстная зависимость (Context Awareness)
Продуктовый замысел предполагает контекст по активной области; таблица ниже описывает возможные интеграции, а не автоматическое чтение документов моделью. В демо приложение формирует текстовый дескрипшен по локальному состоянию:

```
+-------------------------------------------------------------------------------+
| Местонахождение   | Автоматический контекст ИИ                                |
+-------------------+-----------------------------------------------------------+
| Страница Док-тов  | ИИ считывает список файлов во вкладке и Gate Keeper       |
| Лист сметы        | ИИ считывает выделенные строки, цены, объемы сметы        |
| Справочник ТДУ    | ИИ считывает выбранные нормативные базы и регламенты      |
+-------------------------------------------------------------------------------+
```

В текущем прототипе дескрипшен контекста строится по следующим правилам:

* Если открыта панель фильтрации, выводится `Контекст: фильтрация дерева документов · <проект>`.
* Если правая панель находится в техническом режиме pipeline, выводится `Контекст: технические параметры pipeline · <выбранный файл>`.
* Если выбран файл в дереве, выводится `Контекст: выбранный документ · <выбранный файл>`.
* Если активна вкладка `ИИ-анализ комплектности`, но файл не выбран, выводится `Контекст: ИИ-анализ комплектности · <проект>`.
* Если активна вкладка загруженных документов, выводится `Контекст: загруженные документы · <проект>`.
* Название проекта для контекста берется из атрибута `data-project-title` верхнего `.scost-header`. Это позволяет показывать в общем хедере страницы нейтральный title `Документы`, не теряя проектный контекст ИИ-чата.

## 3. Элементы интерактивного окна сообщений

### 3.1. Рендеринг Rich-сообщений
* Поддержка парсинга **Markdown** в сообщениях от ИИ (жирный шрифт, нумерованные списки, таблицы и блоки с формулами).
* Сообщения ИИ отображаются как светлая карточка с отдельным левым бейджем `ИИ`, синим именем ассистента и мягким скруглением `16px`.
* Внутри сообщений ИИ используется компактный вертикальный ритм: заголовки, абзацы и списки не должны создавать большие пустые промежутки.
* Inline-выделения в обратных кавычках отображаются черным цветом с прежней толщиной начертания; красный цвет сохраняется только для error-token уведомлений, например `🔴 Ошибка комплектности`.
* Сообщения пользователя остаются правосторонними с синей заливкой, чтобы визуально отделять запрос пользователя от ответа ассистента.

### 3.2. Группировка истории по дням
* История сообщений автоматически группируется по календарным дням на основе `timestamp` каждого сообщения.
* При смене даты перед первым сообщением нового дня добавляется разделитель даты.
* Разделитель оформляется ненавязчиво: пунктирная горизонтальная линия, по центру — маленькая серая дата на подложке цвета фона чата. Подложка визуально разрывает линию под текстом.
* Для текущего дня используется label `Сегодня`, для предыдущего календарного дня — `Вчера`, для более старых сообщений — дата в формате `15 мая 2026`.
* Разделитель имеет `position: sticky` и прилегает к нижней границе хедера чата без промежуточного зазора, чтобы при прокрутке длинной истории пользователь видел, к какому дню относится текущий фрагмент переписки.
* Отдельная служебная строка `Диалог по комплектности / История и действия` не используется: после хедера сразу начинается область сообщений со sticky-разделителем периода.

### 3.3. Боковая навигационная панель чатов
* Под шапкой дровера расположена рабочая область `.ai-drawer-main`, состоящая из двух колонок: слева постоянная навигационная панель чатов шириной `350px`, справа единый блок активного чата.
* Правая колонка `.ai-chat-thread` содержит область входящих/исходящих сообщений, индикатор набора текста и нижний блок ввода/отправки сообщения. Поэтому поле ввода соответствует ширине именно правого блока сообщений, а не всей ширине дровера.
* Список чатов больше не является dropdown/select и не раскрывается отдельным аккордеоном. Он всегда видим в левой части основной контентной области, чтобы пользователь постоянно видел доступные контексты общения.
* Контейнер навигации использует selector `#chat-workspace-accordion`, но визуально работает как sidebar, а не как accordion. Панель занимает всю доступную высоту от хедера дровера до нижней границы интерфейса, имеет внутренний padding `14px` со всех сторон; футер ввода под ней не располагается.
* В навигационной панели не используется отдельный заголовок `Чаты`. Первым элементом панели является кнопка `Новый чат`.
* Кнопка `Новый чат` выполнена в стиле Secondary: светлая заливка, синяя обводка, синий текст и иконка `+`, hover-состояние с усилением border и легкой тенью.
* При первом входе в прототип автоматически существует базовый чат `Общий чат`. Он хранит стартовую историю сообщений и не смешивается с другими чатами.
* Создание нового чата происходит через существующее окно подтверждения с полем `Название чата (контекст)`. После создания чат добавляется в список и сразу становится текущим активным чатом, а правая лента сообщений переключается на пустую историю нового контекста.
* Каждый чат отображается как карточка без border, outline и левого активного бордера. Карточка содержит название чата и descriptor/мета-строку.
* Активный чат считывается через светло-голубую заливку карточки и тонкий синий border без смещения контента. Radio-кнопки, левый border и дополнительные маркеры активности не используются.
* В строках списка под названием чата выводится мета-строка: `дата последнего обновления · роли участников`, например `26 мая, 08:45 · Сметчик / ИИ-сметчик`.
* У чатов с непрочитанными сообщениями справа в карточке отображается светло-оранжевый бейдж с иконкой письма и количеством непрочитанных.
* При наведении на любую карточку чата справа появляются Ghost-кнопки действий без бордера: редактирование названия и удаление чата. Иконки действий имеют размер `16x16px`.
* Кнопка удаления использует метафору корзины. На hover и focus она окрашивается в красный цвет и показывает tooltip `Удалить чат`.
* Нажатие на кнопку редактирования не выбирает чат, а открывает модальное окно редактирования названия. В поле ввода подставляется текущее название выбранного чата, внизу отображаются кнопки `Отмена` и `Сохранить`.
* Нажатие на кнопку удаления не выбирает чат, а открывает модальное окно подтверждения удаления с кнопками `Отмена` и `Удалить`.
* Если в workspace остается только один чат, кнопка удаления у этого чата не отображается. Единственный чат автоматически считается текущим.
* Если пользователь удаляет текущий активный чат, система выбирает ближайший доступный чат из списка и обновляет историю сообщений без перезагрузки страницы.
* Пользователь может выбрать любой чат из списка. После выбора правая лента сообщений полностью заменяется историей выбранного чата, а отправленные сообщения и ответы ИИ записываются только в активный чат. При выборе чата его `unreadCount` сбрасывается в `0`.
* При выборе чата список не должен автоматически прокручиваться вверх. Текущая позиция `.chat-workspace-scroll` сохраняется, чтобы пользователь мог быстро прокликивать видимые карточки без повторного поиска места в прокрутке.
* Если список чатов не помещается по высоте, вертикальный скролл появляется только внутри `.chat-workspace-scroll`. Правая лента сообщений имеет отдельный независимый скролл.

### 3.4. Поле ввода и вложений
* Поле ввода оформлено как светлая скругленная `pill`-область с placeholder `Задать вопрос сметчику...`.
* Справа внутри области ввода расположена SVG-иконка скрепки для прикрепления локальных документов сметчика в текущий диалог.
* Кнопка отправки — синяя круглая кнопка с SVG-метафорой бумажного самолётика.
* Кнопка голосового ввода не используется и не должна отображаться в интерфейсе.

### 3.5. Динамические функциональные кнопки (Action Buttons)
Под ответом ИИ могут рендериться кнопки для мгновенного выполнения команд в один клик. Они не являются частью пузыря сообщения и отображаются отдельной группой под карточкой ответа.

Поддерживаются любые действия, которые приходят в массиве `actions[]`, например:

* `[Скорректировать цену строки]` — демонстрационное действие с данными строки и цены; запись реальной сметы требует обработчика целевого приложения.
* `[Согласиться]` — пользователь подтверждает предложенный результат аналитики.
* `[Не согласиться]` — пользователь отклоняет предложенный результат аналитики.
* `[Позвать оператора]` — имитированное сообщение оператора. Создание настоящего тикета, передача истории и подключение сотрудника не реализованы.

## 4. Контракт данных: рабочее пространство чатов (State Schema)

Состояние ИИ-сметчика хранится как workspace с активным чатом и массивом независимых чатов. Каждый чат содержит собственный контекст, историю сообщений и дату обновления.

В прототипе workspace дополнительно сохраняется в `localStorage` по ключу `scost.aiChatWorkspace.v1`. Это нужно, чтобы созданные чаты, выбранный активный чат, отредактированные названия, удаление чатов и история сообщений сохранялись после закрытия и повторного открытия дровера в рамках браузера пользователя.

```json
{
  "activeChatId": "chat_general",
  "chats": [
    {
      "id": "chat_general",
      "title": "Общий чат",
      "description": "Открыт сейчас",
      "participantsLabel": "Сметчик / ИИ-сметчик",
      "unreadCount": 0,
      "context": {
        "mode": "general | selected-document | estimate-review | contract-review | commercial-offer | volume-sheet",
        "projectTitle": "Задание на АСОР Бриз Корпус 19",
        "selectedNodeId": "string | null",
        "selectedNodeName": "string | null"
      },
      "createdAt": "2026-05-15T07:35:00.000Z",
      "updatedAt": "2026-05-26T08:46:15.000Z",
      "messages": [
        {
          "id": "string (UUID сообщения)",
          "sender": "ai | user | operator",
          "timestamp": "string (ISO дата и время; используется для времени сообщения и группировки истории по дням)",
          "text": "string (содержимое с поддержкой Markdown)",
          "attachments": [
            {
              "name": "string (имя прикрепленного файла)",
              "url": "string (ссылка на файл)"
            }
          ],
          "actions": [
            {
              "id": "action_agree",
              "label": "Согласиться",
              "payload": { "action": "apply_estimation", "row_id": 1102 }
            }
          ]
        }
      ]
    }
  ]
}
```

Правила хранения:

* `activeChatId` определяет, какая история отображается в `.ai-drawer-messages`.
* При загрузке компонента состояние сначала читается из `localStorage`; если сохраненных данных нет, повреждена структура или отсутствуют чаты, используется стартовый mock-набор `initialChatWorkspace`.
* Новые пользовательские сообщения и ответы ИИ добавляются только в `messages[]` активного чата.
* Стартовый mock-набор чатов должен содержать от `3` до `6` сообщений в каждом чате, чтобы список чатов демонстрировал реальные входящие и исходящие сценарии, а не пустые контейнеры.
* При переключении чата контекст и история предыдущего чата сохраняются без смешивания с новым выбранным чатом.
* `context` является снимком рабочего состояния на момент создания чата: общий режим, выбранный документ или иной тематический сценарий.
* `updatedAt` обновляется при каждом новом сообщении в чате и используется для отображения времени в списке чатов.
* `participantsLabel` хранит роль-состав диалога на уровне пользователя, например `Сметчик / ИИ-сметчик` или `Сметчик / Оператор / ИИ-сметчик`.
* `unreadCount` хранит количество непрочитанных входящих сообщений конкретного чата. Чаты с ненулевым значением показывают счетчик в правой части своей карточки. При выборе чата его счетчик сбрасывается в `0`.

Схема отдельного сообщения:

```json
{
  "id": "string (UUID сообщения)",
  "sender": "ai | user | operator",
  "timestamp": "string (ISO дата и время)",
  "text": "string (содержимое с поддержкой Markdown)",
  "attachments": [
      {
        "name": "string (имя прикрепленного файла)",
        "url": "string (ссылка на файл)"
      }
    ],
    "actions": [
      {
        "id": "action_agree",
        "label": "Согласиться",
        "payload": { "action": "apply_estimation", "row_id": 1102 }
      },
      {
        "id": "action_reject",
        "label": "Отклонить",
        "payload": { "action": "dismiss" }
      }
    ]
}
```
При нажатии динамической кнопки вызывается локальный обработчик `triggerChatAction`. Он имитирует результат; POST-запрос и изменение реальной сметы не реализованы. Будущий обмен требует отдельно согласованного API.

## 5. Связь с программным кодом (API & DOM Спецификация)

Для обеспечения бесшовной связи технического описания с реальной реализацией ниже приведены ключевые программные идентификаторы, DOM-точки монтирования и прямые интерактивные ссылки на исходный код:

### 5.1. DOM-селекторы и Точки монтирования
* **Точка монтирования чата:** `#ai-sidebar-drawer-root` — контейнер для рендеринга чата на сцене.
* **Основная панель чата:** `#ai-drawer` — выдвижная фиксированная панель.
* **Слайдер изменения размера:** `#ai-drawer-resize-handle` — левая drag-зона шириной `6px` с тонкой видимой линией `2px`, стилистически согласованной с разделителем дерева и панели метаданных.
* **Боковая навигация чатов:** `#chat-workspace-accordion` — постоянная левая панель выбора, создания и переключения чатов. Selector сохранен исторически, но визуально элемент больше не является аккордеоном, dropdown или select.
* **Область скролла сообщений:** `#ai-drawer-messages-list` — список истории сообщений.
* **Поле ввода текста:** `#ai-chat-input` — автовысотный инпут `textarea`.
* **Индикатор набора текста:** `#typing-indicator` — блок с анимированными точками.
* **Кнопка вызова чата:** `#btn-trigger-ai-chat` — плавающая кнопка, сохраненная в DOM для совместимости с `window.toggleAIDrawer()`, но скрытая в текущем демо-режиме.

### 5.2. Глобальное JS API (window)
* **Инициализация разметки чата:** `window.initAIDrawer()` — монтирует чат в DOM и вешает обработчики перетаскивания и ввода.
* **Переключение видимости чата:** `window.toggleAIDrawer()` — выдвигает или скрывает панель.
* **Принудительное закрытие:** `window.closeAIDrawer()` — убирает класс `.open`.
* **Закрытие по внешнему клику:** `setupOutsideClickClose()` — один раз подключает обработчик `mousedown`, который закрывает открытый дровер при клике вне панели и вне кнопки вызова чата.
* **Совместимость старого API списка чатов:** `window.toggleChatWorkspaceAccordion()` — оставлен как безопасный legacy-вызов; постоянная навигационная панель остается видимой и перерисовывается без сценария раскрытия/сворачивания.
* **Выбор чата:** `window.selectChatSession(chatId)` — меняет активный чат, обновляет список и историю сообщений.
* **Создание нового чата:** `window.openCreateChatDialog()`, `window.confirmCreateChat()`, `window.closeCreateChatDialog()` — управляют окном создания нового контекста.
* **Редактирование названия чата:** `window.openEditChatDialog(chatId, event)`, `window.confirmEditChat(chatId)` — открывают окно редактирования и сохраняют новое название чата без переключения активного контекста.
* **Слушатель кнопок быстрых действий:** `window.triggerChatAction(actionId, actionType, rowId)` — обрабатывает симуляцию команд ИИ.
