# Компонент: Панель фильтрации документов
`S.Cost / src / components / Filtering / filtering.md`

## 1. Назначение компонента

Панель фильтрации помогает пользователю уточнять список документов в дереве вложений по понятным пользовательским признакам: общему статусу обработки, смысловому типу документа, автору загрузки и техническому формату файла.

Панель открывается по кнопке фильтрации в блоке `Структура вложений` и временно занимает правую область `#metadata-panel-root` вместо карточки метаданных выбранного файла.

Панель не является модальным окном и не перекрывает весь экран. Пользователь остается в контексте вкладки `ИИ-Анализ комплектности`: слева продолжает отображаться дерево документов, справа отображается интерфейс фильтрации.

Поиск и фильтры работают совместно: поиск уточняет текстовое совпадение, фильтры ограничивают набор документов по структурированным атрибутам.

## 2. Файлы компонента

```text
src/components/Filtering/
├── filtering.md
├── filtering.js
└── filtering.css
```

Файлы подключаются в `index.html` по аналогии с остальными компонентами:

* `filtering.css` подключается в блоке компонентных стилей.
* `filtering.js` подключается после `FileTree.js`, потому что панель использует данные дерева и вызывается из кнопки `#tree-filter-trigger`.

## 3. Группы фильтров

Панель содержит четыре пользовательские группы фильтров:

1. **По статусу обработки**
2. **По смысловому типу документа**
3. **По автору загрузки / ФИО**
4. **По техническому формату файла**

Фильтр по отдельным техническим этапам пайплайна не отображается. Для конечного пользователя успешность распаковки, чтения и комплектности как отдельные фильтры является избыточной технической детализацией.

Пользователь фильтрует список по агрегированному статусу обработки документа, а подробность по этапам остается в правой панели метаданных выбранного файла.

## 4. Атрибуты фильтруемой сущности

Фильтрация выполняется не по DOM, а по данным узла дерева в `filter_metadata`.

```json
{
  "filter_metadata": {
    "status": {
      "overall": "red | yellow | loading | gray | green"
    },
    "pipeline": {
      "stages": [
        { "key": "unpack", "status": "green" },
        { "key": "read", "status": "yellow" },
        { "key": "check", "status": "red" }
      ]
    },
    "semantic_type": {
      "key": "rss_estimate",
      "label": "РСС (сметы)"
    },
    "uploaded_by": {
      "filter_key": "смирнов кирилл андреевич",
      "short_name": "Смирнов К.А."
    },
    "technical_format": {
      "extension": "msg",
      "category": "mail | archive | final_document",
      "label": "Почтовое сообщение"
    },
    "tree_context": {
      "ancestor_ids": ["node_1"]
    }
  }
}
```

### 4.1. Статус обработки

Используется `filter_metadata.status.overall`.

Значения:

* `red` — ошибка.
* `yellow` — требует проверки.
* `loading` — выполняется.
* `green` — успешно.
* `gray` — в очереди.

Каждое значение отображается в панели как строка с чекбоксом, цветовым индикатором, названием и счетчиком количества документов.

### 4.2. Технические этапы пайплайна

`filter_metadata.pipeline.stages` остается в данных узла для правой панели метаданных, блока `Статусы обработки` и интерфейса технических параметров пайплайна.

Эти данные не выводятся отдельной группой в панели фильтрации. Фильтры не должны содержать отдельные значения вида `Распаковка: успешно`, `Чтение: ошибка`, `Комплектность: предупреждение`.

Пользовательский фильтр работает только по агрегированному `filter_metadata.status.overall`.

### 4.3. Смысловой тип документа

Используется `filter_metadata.semantic_type.key`.

Примеры значений:

* `asor_task`
* `rss_estimate`
* `working_docs`
* `project_docs`
* `contract`
* `commercial_offer`
* `other`

### 4.4. Автор загрузки / ФИО

Используется `filter_metadata.uploaded_by.filter_key`.

В интерфейсе отображается сокращенная форма из `filter_metadata.uploaded_by.short_name`, если она доступна.

### 4.5. Технический формат файла

Используется `filter_metadata.technical_format.category`.

Значения:

* `mail` — почтовые сообщения.
* `archive` — архивы и контейнеры.
* `final_document` — конечные документы для чтения, включая офисные файлы, PDF, текстовые файлы и изображения.

### 4.6. Контейнерность дерева

Фильтрация использует ту же нормализованную структуру дерева, что и визуальный список файлов.

Родительскими контейнерами считаются только узлы с техническим форматом `.msg`, `.zip`, `.7z`, `.tar`, `.rar`.

Обычные документы (`.pdf`, `.doc`, `.docx`, `.xls`, `.xlsx`, `.jpg`, `.jpeg`, `.png`, `.txt`) не считаются контейнерами даже при ошибочном наличии `children` в исходных mock-данных.

## 5. Правила выбора значений

* Значения выбираются чекбоксами.
* Внутри одной группы разрешен множественный выбор.
* Пользователь может выбирать и снимать любое количество значений без закрытия панели.
* Несколько значений внутри одной группы работают по логике `ИЛИ`.
* Разные группы работают между собой по логике `И`.

Пример:

```text
Статус: Ошибка ИЛИ Требует проверки
И
Формат: Почтовое сообщение
```

Такой фильтр покажет только письма, у которых общий статус равен `red` или `yellow`.

## 6. Применение фильтров

Фильтры применяются по кнопке `Применить фильтры (N)`, где `N` — общее количество выбранных значений во всех группах.

После применения:

* выбранное состояние сохраняется в интерфейсе;
* дерево документов перерисовывается;
* отображаются только подходящие документы и их родительские контейнеры;
* родительские контейнеры автоматически раскрываются, чтобы пользователь видел путь к найденному документу;
* поиск, если заполнен, продолжает работать совместно с фильтрами;
* правая область возвращается к предыдущему состоянию панели метаданных.

Выбор значений внутри панели хранится как черновик. Если пользователь закрывает фильтрацию крестиком, нажимает `Escape` или использует левую иконку возврата в header, черновик сбрасывается и фильтры не применяются.

## 7. Сброс фильтров

Панель поддерживает два уровня сброса:

1. **Сброс группы:** очищает выбранные значения только внутри конкретного аккордеона.
2. **Сбросить всё:** очищает все группы в панели.

Если в группе ничего не выбрано, счетчик выбранных значений и кнопка сброса группы не отображаются.

## 8. Поведение аккордеонов

* Каждый блок можно раскрыть и свернуть.
* В раскрытом состоянии отображается список значений.
* В свернутом состоянии отображается только заголовок группы.
* Если в группе есть выбранные значения, справа отображаются счетчик и кнопка `Сбросить`.
* При наведении на аккордеон его border становится синим.
* По умолчанию раскрыта группа `По статусу обработки`, потому что это основной пользовательский сценарий поиска проблемных документов.
* Header и footer панели остаются фиксированными в пределах правой области метаданных.
* Центральная область `.filtering-groups` является единственной вертикально прокручиваемой зоной.
* Аккордеоны не сжимаются по высоте: если открытых блоков больше, чем помещается в панели, появляется вертикальный scroll внутри `.filtering-groups`.
* Скроллбар `.filtering-groups` стилистически совпадает со скроллбаром списка дерева документов `.tree-scroll-area`.
* Стартовая анимация выполняется только при первом открытии панели. Переключение аккордеонов, выбор чекбоксов и сброс групп не должны заново проигрывать анимацию открытия панели.
* При внутренней перерисовке сохраняется текущая позиция scroll в `.filtering-groups`.

## 9. Header панели фильтрации

Header содержит:

* левую иконку фильтрации на светло-голубой подложке `32x32px` с `border-radius: 8px`;
* расстояние `8px` между подложкой иконки и блоком заголовка/дескрипшена;
* заголовок `Фильтрация` со шрифтовыми параметрами, идентичными имени файла в панели метаданных;
* дескрипшен `Для выполнения фильтрации выберите значения`;
* кнопку закрытия справа.

При наведении на левую иконку метафора фильтрации меняется на стрелку влево. Нажатие на эту область возвращает пользователя к предыдущему состоянию правой панели без применения черновых настроек.

В текущем демо-режиме плавающая кнопка вызова AI-чата скрыта глобально. Если триггер будет возвращен в интерфейс, при открытой панели фильтрации он также должен оставаться скрытым, чтобы не конкурировать с задачей настройки фильтров.

## 10. Связь с фильтруемыми сущностями

Панель фильтрации не хранит собственную копию дерева документов. Она получает данные из `window.treeMockData`, читает `filter_metadata` и передает выбранное состояние обратно в `FileTree`.

DOM-точка монтирования:

* `#metadata-panel-root` — правая область вкладки, в которой обычно отображаются метаданные выбранного документа или пустое состояние.

Глобальные методы:

* `window.openDocumentFilterPanel({ nodes, filters })` — открыть панель.
* `window.onDocumentFiltersApplied(callback)` — зарегистрировать обработчик применения фильтров.
* `window.setDocumentFilterState(filters)` — синхронизировать состояние фильтров извне.
* `window.getDocumentFilterState()` — получить текущее примененное состояние.

Фактическая фильтрация списка выполняется в `FileTree.js`, чтобы дерево, поиск, раскрытие родительских контейнеров и пустые состояния работали единообразно.

Возврат из режима фильтрации выполняется через `window.restoreMetadataPanel()`, который восстанавливает ранее выбранный документ или пустое состояние правой панели.
