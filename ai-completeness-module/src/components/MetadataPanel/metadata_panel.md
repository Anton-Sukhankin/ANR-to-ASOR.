# Компонент: Панель метаданных (Metadata Panel)

Область: компонент самостоятельного `ai-completeness-module`. Основной дровер использует только выбранные ресурсы пакета и имеет [собственный контракт интеграции](../../../../docs/07-check-workspace-target.md). Этот документ нужен при изменении компонента или его реально используемых данных/стилей, а не как обязательный контекст любой задачи. Примеры данных демонстрационные; браузерные функции `window.*` не являются серверным API.


## 1. Назначение компонента
Панель метаданных является правым интерактивным блоком (40% ширины рабочей split-области по умолчанию) вкладки «ИИ-Анализ». Она служит для детального отображения расширенных параметров, аналитических логов и результатов распознавания ИИ для файла, выбранного пользователем в левом блоке дерева вложений.

Правая область также используется как временный контейнер для панели фильтрации документов. При открытии фильтров карточка метаданных скрывается, но выбранный документ сохраняется в состоянии панели и восстанавливается после закрытия фильтрации без применения черновых настроек.

Ширина правой области по умолчанию составляет 40% рабочей split-области, а левый блок дерева документов занимает 60%. Пользователь может изменить соотношение левой и правой панелей через интерактивный разделитель между деревом документов и правой областью; фильтрация и технические параметры pipeline наследуют текущую ширину правой панели.

## 2. Визуальная структура и Wireframe панели

Панель представляет собой вертикальную информационную карточку со следующей структурой элементов:

```
+-------------------------------------------------------------+
| [Иконка] Имя_выбранного_файла.pdf                           |
| 1.2 MB · 12.05.2026 · Иванов И.И. · PDF                     |
+-------------------------------------------------------------+
|  СТАТУСЫ ОБРАБОТКИ                                          |
|  Аккордеон свернут по умолчанию                              |
|  При раскрытии: Распаковка | Чтение ИИ | Комплектность             |
+-------------------------------------------------------------+
|  КЛАССИФИКАЦИЯ ДОКУМЕНТА                                    |
|  Тип при загрузке: Договоры  <->  Тип по ИИ: Задание на АСОР |
|  Уверенность классификации: 92% (круговой индикатор)        |
+-------------------------------------------------------------+
|  [-] ОШИБКИ И СИСТЕМНЫЕ ЛОГИ РАГ                            |
|  Этап "Чтение":                                             |
|  > [12.05 14:15] Предупреждение: Обнаружен размытый текст.  |
|  > Рекомендация: Проверьте качество сканирования страницы 4. |
+-------------------------------------------------------------+
|  [🔧 Панель отладки SuperAdmin ]                            |
|  Время пайплайна: 4.8 сек                                   |
|  [Посмотреть подробные JSON-логи в админке]                 |
+-------------------------------------------------------------+
```

## 3. Описание функциональных элементов

### 3.1. Заголовок выбранного элемента
* Выводит имя файла.
* Под названием файла отображается компактная строка метаданных: технический формат, размер файла, дата загрузки и автор.
* В правой части заголовка размещена одна кнопка overflow-меню с метафорой `три точки`.
* При нажатии на кнопку открывается dropdown с действиями выбранного файла:
  * `Скачать файл` — строка меню с иконкой скачивания;
  * `Пересчитать файл` — строка меню с иконкой обновления/пересчета;
  * `Технические параметры pipeline` — строка меню с иконкой журнала/проверки и переходом правой панели в технический режим.
* Заголовок закреплен в верхней части панели метаданных при прокрутке.
* Прокрутка применяется не ко всей правой панели, а только к основному контенту под заголовком через контейнер `.metadata-scroll-content`; внешний блок правой области остается неподвижным, а scrollbar располагается в правой части прокручиваемого содержимого и визуально повторяет scrollbar списка файлов дерева вложений.
* Блок заголовка компенсирует padding общей правой панели, поэтому визуально занимает всю ширину области метаданных.
* Блок заголовка имеет одинаковый внутренний padding и нижний сплошной border через всю ширину области метаданных.
* Отдельный текстовый title `Карточка документа` не используется: роль идентификатора карточки выполняет имя выбранного файла.

### 3.2. Блок «Статусы обработки»
Блок располагается над классификацией документа и реализован как аккордеон `details.pipeline-overview-section`. При первом открытии карточки метаданных он свернут: в закрытом состоянии отображается только header `Статусы обработки` и круглая Secondary-индикация `24x24 px` со стрелкой вниз/вверх, визуально идентичная контролу раскрытия дерева вложений. После раскрытия показывает текущее состояние трех этапов pipeline для выбранного файла.

Состояние раскрытия хранится на уровне `window.metadataPanelState.pipelineOverviewExpanded`, а не внутри конкретного документа. Если пользователь раскрыл аккордеон у одного выбранного файла, при переключении на другой файл аккордеон остается раскрытым и показывает уже статусы нового выбранного файла. Если пользователь свернул аккордеон, при последующих переключениях между файлами он остается свернутым.

* **Распаковка:** техническое извлечение вложений из контейнеров, архивов и писем.
* **Чтение ИИ:** извлечение текста, OCR и первичный анализ содержимого документа.
* **Комплектность:** проверка смысловых связей, обязательных вложений и расхождений.
* Источник данных — `fileNode.pipeline_status`, где этапы представлены ключами `unpack`, `read`, `check`.
* Каждый этап отображается отдельной карточкой: сверху метафора этапа на круглой подложке с маленьким бейджем состояния, ниже название этапа, текст состояния и поясняющее сообщение.
* Цвет, иконка и текст состояния определяются значением этапа:
  * `green` — `Успешно`;
  * `loading` — `Выполняется`;
  * `gray` — `В очереди`;
  * `yellow` — `Требует проверки`;
  * `red` — `Ошибка`.
* Если в `metadata_details.logs[]` есть запись по соответствующему этапу, блок использует ее текст как пояснение. Если записи нет, выводится короткий fallback-текст по состоянию.

### 3.3. Блок «Классификация документа»
Объединенный блок показывает сопоставление пользовательской и автоматической классификации в одной карточке.

* **Тип при загрузке:** Значение типа документа, назначенное пользователем вручную при загрузке во Вкладке 1.
* **Тип по версии ИИ:** Демонстрационное значение классификатора из данных; нейросеть в браузере не запускается.
* **Уверенность классификации:** Показатель точности ИИ-модели (`Confidence Score`, %), отображаемый в виде кругового индикатора справа от сопоставления:
  * `90% - 100%`: Зелёная шкала (Высокая уверенность).
  * `70% - 89%`: Жёлтая шкала (Средняя уверенность).
  * `Менее 70%`: Красная шкала (Низкая уверенность).
* Текстовая оценка точности (`Высокая`, `Средняя`, `Низкая`) выводится в правой части заголовка блока, напротив названия `Классификация документа`.

Две области типа разделены тонкой вертикальной линией цвета border карточки. Центральная иконка сопоставления располагается поверх разделителя и визуально связывает пользовательский тип с результатом ИИ.

Блок заменяет прежние два отдельных раздела: `Сопоставление типов документа` и `Уверенность классификации ИИ`. Это делает связь между результатом классификации и степенью доверия к нему более очевидной.

### 3.4. Блок «Кросс-требования комплектности (Смысловые связи)»
* Подготовленные в данных результаты извлечения перекрёстных ссылок; сам разбор текста не входит в компонент.
* Каждая позиция показывает название или тип требуемого документа, обоснование требования и статус наличия.
* Если ИИ находит упоминание смежного документа (например, конкретного Приложения, Договора или Коммерческого предложения), панель визуально подсвечивает:
  * `Приложен` / `green` — файл присутствует в загруженном пакете.
  * `Отсутствует` / `red` — смежный документ упомянут в тексте, но отсутствует в пакете.
* Обоснование требования показывает, почему ИИ решил, что смежный файл нужен для проверки комплектности.
* Позиции отображаются как строки списка: слева круглая подложка с иконкой состояния, по центру название и пояснение, справа статусный бейдж.
* Пояснение выводится без отдельной подписи `Контекст извлечения` / `Обоснование` и без кавычек.

Контракт элемента `metadata_details.crossLinks[]`:

```json
{
  "text": "Договор №12-А",
  "status": "green | red",
  "context": "В тексте текущего документа есть указание, что работы выполняются согласно Договору №12-А."
}
```

Правила отображения:

* `text` выводится как требуемый документ или тип документа.
* `context` выводится как короткое пояснение без кавычек и без служебного label. Если поле отсутствует в старых данных, интерфейс формирует fallback-пояснение на основе `text` и `status`.
* `status` управляет цветом иконки, подложки и бейджа наличия.

### 3.5. Комментарии
* Блок показывает комментарии, связанные именно с выбранным файлом дерева.
* Основной источник данных — `metadata_details.comments[]`.
* Если `comments[]` отсутствует, интерфейс использует fallback из `metadata_details.originalComment`.
* Если комментариев нет или `comments: []`, отображается заглушка `Комментарии отсутствуют`.
* Каждая позиция комментария содержит автора, дату и текст комментария.

Контракт элемента `metadata_details.comments[]`:

```json
{
  "author": "Мустафаева Эльвина Сейрановна",
  "date": "25.02.2026 10:45",
  "text": "Официальное задание на АСОР для Бриз Корпус 19."
}
```

### 3.6. Аккордеон системных логов RAG
* По умолчанию развернут, если у выбранного файла есть хотя бы один статус `🔴 Ошибка` или `🟡 Требует проверки`.
* Показывает точное время инцидента, этап пайплайна (Распаковка, Чтение, Комплектность), на котором произошел сбой, и описание проблемы.
* Отображается как самостоятельный аккордеон без дополнительного внешнего контейнера `metadata-section`.
* Визуально использует ту же структуру, что и `Технические параметры пайплайна`: header с title, круглой Secondary-индикацией раскрытия/сворачивания `24x24 px` и нижним border, затем контентная область логов.

### 3.7. Технические параметры самостоятельного демо

Ролевое ограничение «для супер-админов» относится к будущей интеграции; прототип не является средством контроля доступа. Эти панели не входят в основной пользовательский путь дровера проверки.
* Интерфейс `Технические параметры pipeline` открывается отдельным режимом правой панели через dropdown-меню в заголовке карточки метаданных.
* При открытии технического режима основная карточка метаданных временно заменяется диагностическим экраном выбранного файла.
* В хедере технического режима есть кнопка возврата к карточке метаданных, заголовок `Технические параметры pipeline`, имя выбранного файла и краткая строка его атрибутов.
* Технический режим динамически связан с текущим выбранным узлом дерева и получает значения именно из `fileNode.metadata_details` выбранного файла.
* Если пользователь выбирает другой файл в дереве при активном техническом режиме, правая панель остается в режиме `Технические параметры pipeline` и перерисовывает технические параметры уже для нового выбранного файла.
* Возврат из технического режима к обычной карточке метаданных выполняется только через кнопку `Вернуться к метаданным` в хедере технического режима.
* Для выбранного файла отображаются:
  * **ID документа** — `fileNode.id`;
  * **Инициатор загрузки** — `metadata_details.authorName`;
  * **Использованная LLM-модель** — `metadata_details.llmModel`;
  * **Execution time** — `metadata_details.pipelineTime`;
  * **Количество чанков текста** — `metadata_details.textChunks`;
  * **Количество токенов** — `metadata_details.tokenCount` или расчетное значение на основе чанков;
  * **Количество вложенных файлов** — вычисляется рекурсивно по `children`;
  * **Ошибки / проверки** — вычисляются по `pipeline_status` и `metadata_details.logs`;
  * **OCR** — вычисляется по статусу этапа `read`;
  * **Векторизация** — `metadata_details.vectorizationResult` или fallback по количеству чанков.
* Терминальный лог собирается из `metadata_details.embeddingLogs` и дополняется контекстом выбранного файла: ID, именем файла, размером, временем выполнения, количеством чанков, моделью и счетчиками предупреждений/ошибок.
* Кнопка `Скопировать лог` копирует лог именно выбранного файла.
* Терминальный блок расположен под заголовком `Логика коннектора эмбеддингов` и занимает основную часть технического интерфейса.
* Technical-panel actions (`copy-pipeline-log`, `open-technical-pipeline`, `restore-metadata-panel`, `open-node-json`, `close-bottom-drawer`) are bound locally after each right-panel render through `bindMetadataPanelActions(root)` and are also supported by a delegated `data-metadata-action` listener on the capture phase. This keeps dropdown clicks and technical-mode actions working after the metadata panel is re-rendered. If `window.treeMockData` lookup fails, the interface falls back to `window.metadataPanelState.selectedNode` or `window.activeTreeNodeId`.
* Internal lookup uses `findMetadataNodeInTree(...)`; the public API remains `window.findMetadataNodeById(nodeId)`. The names are intentionally separated so the browser global function does not shadow the recursive helper and break technical-mode opening.
* В терминальном выводе уровни событий имеют цветовую индикацию: `INFO` и `SUCCESS` — зеленые, `WARN` — желтые, `ERROR` — красные, `SYS` — синие.
* Кнопка `Посмотреть подробный JSON узла` открывает нижний drawer с JSON-структурой выбранного узла. Для JSON используется отдельный модификатор `is-node-json`: drawer выше стандартного режима логов на 250 px, чтобы JSON не отображался узкой полосой с неудобным внутренним скроллом.
* Если `metadata_details.pipelineMetadataLoading = true`, отображается skeleton loader технических параметров и placeholder строк терминала.
* Если у выбранного файла нет pipeline metadata, отображается состояние `Технические параметры пайплайна отсутствуют`.

### 3.8. Контекстное меню действий
Действия выбранного файла размещаются в правой части заголовка карточки внутри dropdown-меню, которое открывается кнопкой с метафорой `три точки`.

* **Скачать файл** — вызов демонстрационного обработчика выбранного узла с иконкой скачивания; наличие пункта не означает доступ к исходному документу.
* **Пересчитать файл** — локальная симуляция изменения статусов выбранной ветки с иконкой обновления. Реальный парсинг и RAG-анализ не запускаются.
* **Технические параметры pipeline** — открывает отдельный технический режим правой панели с основными параметрами и терминальным логом коннектора эмбеддингов выбранного файла.

Кнопка меню имеет tooltip, а сами действия представлены текстовыми строками с иконками, чтобы не перегружать закрепленный хедер отдельными кнопками.

## 4. Спецификация взаимодействия (Interaction Contract)

1. **Состояние по умолчанию (Ничего не выбрано):**
   * Отображает стартовое Empty State до выбора документа: центрированную светло-голубую PNG-иллюстрацию `src/assets/metadata-empty-illustration.png` со связкой дерева файлов и аналитической карточки, уменьшенную на 40% относительно исходного размера блока, с внутренним отступом контейнера 24 px со всех сторон, заголовок `Выберите документ слева, чтобы увидеть подробный анализ` размером 16 px, поясняющий текст размером 14 px и три карточки ожидаемых результатов (`Статистика`, `Заключение ИИ`, `Логи пайплайна`) с заголовками 14 px, описаниями 12 px и синими контурными иконками; карточка `Статистика` использует метафору кривой графика, а карточка `Заключение ИИ` — метафору круга с галочкой с той же толщиной начертания, что и остальные иконки блока.
2. **Связь с Деревом вложений:**
   * При клике на любой узел дерева файлов левая часть отправляет событие `onNodeSelect(nodeId)`.
   * В обычном режиме панель метаданных рендерит карточку выбранного файла.
   * При повторном клике по уже активному файлу дерево снимает выбор и правая панель снова отображает стартовое Empty State.
   * В техническом режиме выбор нового узла не закрывает технический экран: обновляются только технические параметры, логи и JSON-контекст выбранного файла.
3. **Временный режим фильтрации:**
   * При клике по кнопке фильтрации в дереве правая область переходит в режим панели `Filtering`.
   * Закрытие фильтрации крестиком, клавишей `Escape` или левой иконкой возврата восстанавливает предыдущую карточку документа или пустое состояние.
   * Применение фильтров обновляет дерево документов и затем возвращает правую область к предыдущему состоянию.

## 5. Связь с программным кодом (API & DOM Спецификация)

Ниже перечислены браузерные точки связи и исходные файлы. Наличие идентификатора не подтверждает серверную операцию; поведение проверяется по обработчику и наблюдаемому результату.

### 5.1. DOM-селекторы и Точки монтирования
* **Точка монтирования панели:** `#metadata-panel-root` — контейнер, в который рендерится панель.
* **Стартовое пустое состояние:** `.metadata-empty-state` — onboarding-экран правой панели до выбора документа; включает `.empty-hero-illustration` с изображением `src/assets/metadata-empty-illustration.png` и `.empty-benefits`.
* **Главный контейнер карточки:** `.metadata-card` — элемент с анимацией появления.
* **Прокручиваемая область карточки:** `.metadata-scroll-content` — внутренний flex-контейнер под `.metadata-header`, который принимает вертикальный скролл основной контентной части карточки метаданных и технического режима. Дочерние секции внутри этой области не сжимаются по высоте: аккордеоны, карточки классификации, комментарии и системные логи сохраняют естественную высоту, а нижние блоки становятся доступны через прокрутку.
* **Блок статусов обработки:** `.pipeline-overview-section` — свернутый по умолчанию аккордеон; `.pipeline-overview-summary` — header с круглой Secondary-индикацией `.accordion-arrow`; `.pipeline-stage-card` — карточки трех этапов pipeline выбранного документа внутри раскрытого контента.
### 5.2. Глобальное JS API (window)
* **Инициализация правой панели:** `window.initMetadataPanel()` — рендерит стартовое Empty State при загрузке прототипа.
* **Динамическое обновление аналитики:** `window.updateMetadataPanel(fileNode)` — парсит параметры сущности и отрисовывает карточку.
* **Восстановление предыдущего состояния:** `window.restoreMetadataPanel()` — возвращает правую область из режима фильтрации к выбранному документу или Empty State.
* **Симуляция локального пересчета:** `window.triggerFileRecalc(nodeId)` — запускает анимацию спиннеров для выбранной строки и обновляет панель.
* **Открытие технического режима:** `window.openTechnicalPipelinePanel(nodeId)` — заменяет карточку метаданных интерфейсом технических параметров выбранного файла.
* **Поиск узла для технического JSON:** `window.findMetadataNodeById(nodeId)` — рекурсивно находит выбранный узел в `window.treeMockData`, включая вложенные файлы.
* **Копирование pipeline-лога:** `window.copyPipelineLog(nodeId)` — копирует терминальный лог выбранного файла.
* **Нижний drawer диагностики:** `window.openMetadataBottomDrawer(type, nodeId)` — открывает нижнюю панель для `connector-log` или `node-json`; для `node-json` добавляет класс `is-node-json`, для логов — `is-connector-log`.
* **Закрытие нижнего drawer:** `window.closeMetadataBottomDrawer()` — закрывает нижнюю панель диагностики.
