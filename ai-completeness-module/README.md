# Переносимый модуль «ИИ-Анализ комплектности»

Эта папка является локализованной копией текущего прототипа анализа комплектности S.Cost. Ее можно перенести в другой проект как самостоятельный UI-пакет, а затем адаптировать под структуру, API и дизайн-систему целевого продукта.

## Назначение

Пакет сохраняет:

* интерфейс вкладки `ИИ-Анализ комплектности`;
* дерево вложенных документов;
* общий статус РВЕ и сводную статистику;
* правую панель метаданных, фильтрацию и технические параметры pipeline;
* боковой чат `ИИ-Сметчик S.Cost` со списком чатов, историями сообщений и локальным состоянием;
* CSS-стили, mock-данные, иллюстрацию заглушки и связанную документацию.

## Быстрый запуск

Откройте `index.html` из этой папки в браузере. Файл подключает CSS и JS локально через относительные пути, поэтому пакет не зависит от исходного корня проекта.

Единственная внешняя визуальная зависимость текущего HTML - Google Fonts. Если целевой проект должен работать полностью офлайн, шрифты нужно заменить на локальные или на шрифты дизайн-системы целевого продукта.

## Важные точки интеграции

При переносе в другой проект важно сохранить или адаптировать следующие DOM-точки:

* `#standard-upload-root` - стандартная вкладка загруженных документов;
* `#tree-summary-cards-root` - общий статус РВЕ и сводная статистика;
* `#file-tree-root` - дерево вложений;
* `#metadata-panel-root` - правая панель метаданных, фильтрации и технических интерфейсов;
* `#ai-sidebar-drawer-root` - боковой чат ИИ-сметчика;
* `#btn-trigger-ai-chat` - сохраненный, но скрытый в текущем демо триггер открытия чата.

Порядок подключения скриптов в `index.html` важен:

```html
<script src="src/components/AICompletenessTab/StandardUploadTab.js"></script>
<script src="src/components/FileTree/FileTree.js"></script>
<script src="src/components/Filtering/filtering.js"></script>
<script src="src/components/MetadataPanel/MetadataPanel.js"></script>
<script src="src/components/AISidebarDrawer/AISidebarDrawer.js"></script>
<script src="src/app.js"></script>
```

## Данные и состояние

Пакет содержит демонстрационные данные:

* `src/components/FileTree/mockTreeData.json` - дерево документов и атрибуты фильтрации;
* `src/components/AISidebarDrawer/mockChatHistory.json` - сохраненный формат истории чатов;
* `src/components/ThreadedRemarks/mockRemarksData.json` — остаточные данные неиспользуемого компонента, не обязательный контекст и не действующий контракт обсуждений.

Для надежной работы через `file://` часть mock-данных также продублирована прямо в JS-компонентах. При интеграции с backend/API нужно заменить демонстрационный источник данных, но сохранить атрибутивный контракт сущностей, описанный в документации компонентов.

Чат дополнительно хранит рабочее пространство в `localStorage` по ключу `scost.aiChatWorkspace.v1`. В продуктовой интеграции это состояние лучше перенести в API или в единое клиентское хранилище целевого проекта.

## Глобальное JS API

Основные публичные функции прототипа:

* `window.initFileTree()`;
* `window.reRenderTree()`;
* `window.onFileSelected(callback)`;
* `window.initMetadataPanel()`;
* `window.updateMetadataPanel(fileNode)`;
* `window.restoreMetadataPanel()`;
* `window.openDocumentFilterPanel(options)`;
* `window.initAIDrawer()`;
* `window.toggleAIDrawer()`;
* `window.openCreateChatDialog()`;
* `window.triggerFileRecalc(nodeId)`;
* `window.triggerRAGPipelineSim()`.

## Документация

Копия документации находится в `docs/` и в markdown-файлах внутри `src/components/*/`. Для изменений UI внутри пакета используйте тот же маршрут:

```bash
node scripts/docs-sync-check.js <changed-file>
```

## Границы демо-реализации

Это переносимый prototype snapshot, а не production-модуль. В нем нет реального backend, авторизации, загрузки файлов, настоящего скачивания документов и реальных RAG/API-вызовов. Эти обязанности должны быть подключены в целевом проекте отдельно.

## Чек-лист переноса

1. Перенести папку `ai-completeness-module/` в целевой проект.
2. Подключить `index.html` как временный демо-экран или перенести DOM-точки в нужный layout.
3. Подключить CSS-файлы или перенести токены в дизайн-систему целевого проекта.
4. Заменить mock-данные на API, сохранив поля сущностей документов, статусов и чатов.
5. Проверить сценарии: выбор файла, снятие выбора, фильтрация, пересчет статуса ветки, ресайз split-панелей, открытие/закрытие чата и переключение чатов.
6. Обновить документацию целевого проекта, если контракт или пользовательский путь будут переработаны.
