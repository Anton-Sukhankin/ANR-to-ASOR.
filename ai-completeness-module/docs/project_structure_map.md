# Карта целевой структуры проекта «ИИ-Сметчик» (S.Cost)
`S.Cost / docs / project_structure_map.md`

Настоящий документ описывает целевую компонентно-ориентированную структуру каталогов для интеграции функционала «ИИ-Сметчик». Данная структура основана на принципе **колокации (Co-location)** и призвана обеспечить независимость разработки компонентов дизайнером и фронтендером с легким переходом от прототипа к рабочей интеграции.

---

## 2. Назначение папок и распределение файлов

Глобальная папка `docs/` содержит проектные документы, которые описывают не один компонент, а правила и связи всего прототипа:

1. **`README.md`:**
   * Входная точка документации и оглавление спецификаций.
2. **`project_structure_map.md`:**
   * Карта структуры проекта и правила размещения файлов.
3. **`component_registry.json`:**
   * Машинно-читаемый индекс связей между UI-файлами, mock-данными и markdown-документацией.
   * Используется как маршрут после изменения UI: показывает, какие документы нужно проверить и при необходимости обновить.
4. **`ui_docs_sync_workflow.md`:**
   * Обязательная инструкция `UI + Docs`: изменение интерфейса должно сопровождаться проверкой связанной документации.
5. **`design_system_statuses.md`:**
   * Единые правила статусов, цветовой индикации и отображения состояний.

Корневой файл `README.md` описывает назначение переносимой копии, точки интеграции, границы демо-реализации и чек-лист переноса. Файл `module_manifest.json` дает машинно-читаемый состав пакета: активные компоненты, assets, mock-данные, mount-point'ы и внешние зависимости.

Корневой файл `AGENTS.md` фиксирует правило `UI + Docs` как проектную инструкцию для Codex. Скрипт `scripts/docs-sync-check.js` использует `component_registry.json` и показывает, какие документы нужно проверить для измененных UI-файлов.

Каждая папка в каталоге `src/components/` является независимым модулем, содержащим четыре типа ресурсов:

1. **Документация (`*.md`):**
   * Содержит детальные бизнес-требования, описания визуальных элементов и логику переходов состояний конкретного компонента.
   * Находится в ведении системного аналитика / архитектора и служит ТЗ для разработки.
2. **Представление (`*.html` или `*.js` / `*.tsx`):**
   * HTML-разметка или JSX-код компонента. Отвечает за рендеринг структуры на экране.
   * Рендерится динамически на основе файлов данных (`mock*.json`).
3. **Стили (`*.css`):**
   * Локальные CSS-стили, относящиеся исключительно к элементам этого компонента (например, форматные подложки и статусные точки строк в `FileTree.css` или слайдер ресайза в `AISidebarDrawer.css`).
   * Наследует глобальные переменные и классы из корневого `index.css`.
4. **Стейт данных (`mock*.json` или `mock*.js`):**
   * Хранит массивы сущностей с параметрами и динамически изменяемыми значениями.
   * Служит «контрактом» обмена данными. При переносе в прод-среду файлы просто заменяются на Fetch-запросы к API.

## 3. Поэтапный план миграции и реализации

Для плавного перехода от текущего состояния проекта к целевой структуре мы выполним следующие 3 этапа:

### Этап А: Создание папок и миграция документации (Текущий шаг)
* [ ] Создать структуру папок в директории `src/components/`.
* [ ] Перенести ранее созданные файлы спецификаций из глобальной папки `docs/components/` в их целевые папки компонентов:
  * `ai_completeness_tab.md` $\rightarrow$ `src/components/AICompletenessTab/`
  * `file_tree_and_pipelines.md` $\rightarrow$ `src/components/FileTree/`
  * `metadata_panel.md` $\rightarrow$ `src/components/MetadataPanel/`
  * `ai_sidebar_drawer.md` $\rightarrow$ `src/components/AISidebarDrawer/`
  * `threaded_remarks_system.md` $\rightarrow$ `src/components/ThreadedRemarks/`
* [ ] Обновить пути в главном оглавлении `docs/README.md`.

### Этап Б: Реализация «Контрактов данных» (Mock State)
* [ ] Создать файлы `mockTreeData.json`, `mockChatHistory.json`, `mockRemarksData.json` с массивами сущностей и динамическими параметрами в соответствующих папках.

### Этап В: Создание презентационных прототипов (HTML/CSS)
* [ ] Сформировать шаблоны верстки компонентов, которые рендерят интерфейс на основе подготовленных Mock-данных.
* [ ] Написать скрипт-симулятор динамического изменения стейтов (например, прохождение РАГ-статусов по клику на кнопку).
