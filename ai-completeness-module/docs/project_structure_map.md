# Размещение файлов пакета комплектности

Область — только `ai-completeness-module`, не структура всего проекта S.Cost. [README](../README.md) владеет запуском и интеграцией; [манифест](../module_manifest.json) — составом и точками подключения; [реестр](component_registry.json) — маршрутами UI → документация.

## Правила размещения

Документ компонента находится рядом с его JS, CSS и демоданными в `src/components/<Component>/`. Добавлять отдельную папку или четыре обязательных файла для каждого компонента не требуется: хранятся только реально нужные ресурсы.

Общие статусы находятся в [design_system_statuses.md](design_system_statuses.md), порядок проверки — в [ui_docs_sync_workflow.md](ui_docs_sync_workflow.md). Индексы содержат ссылки и границы, а не повторяют описание компонентов.

`src/app.js` связывает компоненты самостоятельной страницы; `src/index.css` хранит общие стили пакета, `src/assets/` — используемые изображения. Runtime-иллюстрация пустой панели не является удаляемым дизайн-референсом.

## Изменение состава

При добавлении, переносе или удалении компонента проверить исполняемые подключения, манифест, реестр и ближайший индекс. При интеграции в основной дровер проверить его потребителей; само наличие папки не означает подключение компонента.

У ThreadedRemarks остались неиспользуемые CSS и mock-данные, но нет смонтированного JS-интерфейса. Они не входят в обязательный контекст; отдельная спекулятивная спецификация удалена. Очистка исходного кода не входит в редактуру документации.

## Граница готовности

Прежний план «создать папки / перенести спецификации / добавить mock-файлы» больше не является активным: эти папки и ресурсы уже существуют. Продуктовая миграция не сводится к замене mock на fetch — отдельно нужны контракт, ошибки, права, хранение и приёмка. Общий активный план находится в [плане проекта](../../PROJECT_PLAN.md).
