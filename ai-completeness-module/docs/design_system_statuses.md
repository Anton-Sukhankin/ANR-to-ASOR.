# Дизайн-система: Статусы и цветовая индикация «ИИ-Сметчик»

Документ владеет значениями статусов и визуальным кодированием компонентов самостоятельного пакета. Он не задаёт глобальную дизайн-систему S.Cost и не обещает наличие API.

---

## 1. Итог самостоятельного демо

Область этого документа — `ai-completeness-module`. В основном дровере действует [собственный контракт итога](../../docs/07-check-workspace-target.md): два итоговых состояния и промежуточная обработка, без жёлтого итога. Цвета отдельных файлов могут переиспользоваться без переноса всех бизнес-состояний самостоятельной страницы.

Ранее описанная передача сметчику после трёх автоматических попыток не имеет подтверждённого исполняемого процесса или согласованного серверного контракта. Лимит попыток и правила ролей не устанавливаются этим документом.

### Агрегированный статус РВЕ в верхней аналитической зоне

Компонент `FileTree` выводит общий статус РВЕ в едином верхнем аналитическом блоке вместе со сводной статистикой. В прототипе статус рассчитывается из дерева, серверный формат ещё не определён. Обозначения ниже относятся к демо и не являются принятым API.

| Обозначение демо | UI-смысл | Цветовой тон | Когда отображается |
| --- | --- | --- | --- |
| `Allowed` / `Done` | `Комплектность подтверждена` | Зеленый | Все обязательные требования закрыты, ошибок и предупреждений нет |
| `Processing` | `Выполняется проверка комплектности` | Синий | Документ еще проходит распаковку, чтение или проверку комплектности |
| `Manual Review` | `Требуется ручная проверка` | Оранжевый | Критических ошибок нет, но есть предупреждения или сомнения ИИ |
| `Blocked` | `Комплектность не подтверждена` | Красный | Есть критические ошибки, отсутствующие обязательные требования или нечитаемые файлы |

Карточка общего статуса РВЕ является информационной. Операционные действия `Перейти к проблеме` и `Пересчитать проверку` размещаются в блоке `Структура вложений`, чтобы пользователь выполнял их рядом с конкретными проблемными позициями и контекстом дерева.

## 2. Технические статусы РАГ-пайплайна (Дочерние вложения)

Применяются во внутренних деревьях вложений для визуализации состояния трех технологических этапов (*Распаковка*, *Чтение*, *Комплектность*).

```
+-----------------------------------------------------------------------------------+
| Статус индикатора        | Вид индикатора        | Hex-код   | Применение         |
+--------------------------+-----------------------+-----------+--------------------|
| 🔘 Очередь / Пропуск     | Контурный тонкий круг | `#BDBDBD` | Шаг ожидает /      |
|                          |                       |           | не требуется       |
| 🔵 Выполняется           | Спиннер / активный круг| `#1976D2` | Шаг в процессе     |
| 🟢 Успешно               | Заполненный с галочкой| `#2E7D32` | Успешное выполнение|
| 🟡 Требует проверки      | Заполненный со знаком!| `#F57C00` | Нужен ручной контроль|
| 🔴 Сбой / Ошибка         | Заполненный с крестиком| `#C62828` | Критическая ошибка |
+-----------------------------------------------------------------------------------+
```

## 3. Отображение и анимация

### 3.1. Интерактивные состояния «В процессе» (Loader)
* Если этап находится в процессе выполнения (статус `loading` / `Выполняется`), статический серый маркер заменяется на **прелоадер (spinner)** с плавным вращением на 360 градусов.
* В списке файлов дерева вложений детальные этапы `Распаковка / Чтение / Комплектность` не отображаются как отдельные `Р / Ч / К`-индикаторы. В строке агрегированный статус встроен в форматную подложку:
  * `Выполнено` — светло-зеленая подложка, темно-зеленая аббревиатура и без точки;
  * `В обработке` — светло-голубая подложка, синяя аббревиатура и синяя точка;
  * `Требует проверки` — светло-оранжевая подложка, темно-оранжевая аббревиатура и оранжевая точка;
  * `Невыполнено` — светло-красная подложка, темно-красная аббревиатура и красная точка.
* Для строк дерева, требующих внимания, дополнительно используется левый статусный бордер на всю высоту строки:
  * `Требует проверки` — оранжевый бордер `1.5px`;
  * `Невыполнено` — красный бордер `1.5px`.
* Для `Выполнено` и `В обработке` левый бордер не используется, чтобы успешные и промежуточные строки не конкурировали с проблемными позициями.
* Детальная расшифровка этапов остается в правой панели метаданных выбранного файла.
* Для доступности форматная подложка содержит текстовую подсказку со связкой `формат + статус`, например `PDF, статус: Требует проверки`.
* Состояние `gray` / `В очереди` остается спокойным нейтральным состоянием без анимации.
* При переходе из состояния «В процессе» в финальный статус (зелёный/жёлтый/красный) цвет плавно меняется с использованием CSS-перехода: `transition: background-color 0.3s ease, border-color 0.3s ease`.

### 3.2. Доступность (Accessibility / Contrast)
* Контраст текста и индикаторов должен быть проверен на фактических подложках перед приёмкой; в этом документе нет результатов измерения или подтверждения соответствия WCAG AA.
* Крупные индикаторы в карточке метаданных не должны полагаться **только** на цвет. Обязательно использование уникальных вспомогательных глифов/иконок внутри круга (`галочка`, `восклицательный знак`, `крестик`), чтобы пользователи с цветовой слепотой (дальтонизмом) могли мгновенно дифференцировать статусы.
* В компактном списке файлов статусная подложка дополнительно сопровождается `title` / `aria-label` со связкой `формат + статус`, чтобы цветовая кодировка не была единственным источником смысла.
