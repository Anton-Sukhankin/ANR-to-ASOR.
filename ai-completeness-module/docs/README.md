# Документация технических компонентов прототипа «ИИ-Сметчик» (S.Cost)

Данная директория содержит детальные технические описания интерфейсов и логики работы компонентов, разработанных на основе аналитики встреч проекта **S.Cost**.

Эти спецификации спроектированы для быстрой передачи в разработку (Hand-Off) и служат «единым источником истины» как для ИИ-ассистентов, так и для разработчиков.

---

## Индексы и правила синхронизации

### 1. [Индекс связей компонентов и документации](./component_registry.json)
* **Назначение:** Машинно-читаемая карта связей между UI-файлами, mock-данными и markdown-документацией.
* **Когда используется:** После любой правки интерфейса, поведения, статусов, данных или пользовательского сценария.

### 2. [UI + Docs: маршрут синхронизации](./ui_docs_sync_workflow.md)
* **Назначение:** Рабочая инструкция, по которой Codex проверяет и обновляет документацию после изменений UI.
* **Правило:** Для пользователя обновление docs считается частью UI-задачи и не требует отдельной команды.
* **Быстрая проверка маршрута:** `node scripts/docs-sync-check.js <changed-file>`.

### 3. [Паспорт переносимого пакета](../README.md)
* **Назначение:** Описание состава локализованной копии, точек подключения, границ демо-реализации и чек-листа переноса в другой проект.
* **Манифест:** `module_manifest.json` в корне пакета содержит машинно-читаемый список включенных файлов, активных компонентов, mount-point'ов и интеграционных границ.

## Структура спецификаций компонентов

Нажмите на ссылку ниже, чтобы перейти к техническому описанию соответствующего компонента:

### 1. [Вкладка «ИИ-Анализ комплектности»](../src/components/AICompletenessTab/ai_completeness_tab.md)
* **Назначение:** Описание segment-control для переключения режимов, сводных карточек статистики пакета документов, двухвкладочной рабочей области экрана загрузки документов, resize-разделителя split-панелей, виджета «Gate Keeper», системы алертов о некомплекте документов и блоков управления для супер-администраторов.
* **Файл:** `src/components/AICompletenessTab/ai_completeness_tab.md`

### 2. [Дерево вложений и РАГ-статусы](../src/components/FileTree/file_tree_and_pipelines.md)
* **Назначение:** Логика рекурсивного парсинга вложенных архивов (`.zip`/`.rar`/`.7z`/`.tar`) и писем (`.msg`), пятисостоянийная схема РАГ-пайплайнов (распаковка, чтение, сверка) и JSON-контракт динамических данных.
* **Файл:** `src/components/FileTree/file_tree_and_pipelines.md`

### 3. [Панель метаданных (Metadata Panel)](../src/components/MetadataPanel/metadata_panel.md)
* **Назначение:** Спецификация правой интерактивной информационной панели (40% ширины рабочей split-области по умолчанию). Описывает вывод «градусника уверенности ИИ», логов системных ошибок РАГ, сопоставления типов документов и отладочных панелей для супер-администраторов.
* **Файл:** `src/components/MetadataPanel/metadata_panel.md`

### 4. [Масштабируемый боковой чат с ИИ (AI Drawer)](../src/components/AISidebarDrawer/ai_sidebar_drawer.md)
* **Назначение:** Сквозной правый выдвижной чат с ручным ресайзом, автоматическим определением контекста, системным аккордеоном `Список чатов`, независимыми историями диалогов, поддержкой Markdown и функциональных кнопок действий.
* **Файл:** `src/components/AISidebarDrawer/ai_sidebar_drawer.md`

### 5. [Тред-система замечаний (Threaded Remarks)](../src/components/ThreadedRemarks/threaded_remarks_system.md)
* **Назначение:** Замена хаотичных писем на GitLab MR-style ветви обсуждений по строкам сметы, логика бизнес-блокировок несогласованных тредов и схема интеграции переписки с ИИ-моделью.
* **Файл:** `src/components/ThreadedRemarks/threaded_remarks_system.md`

### 6. [Панель фильтрации документов](../src/components/Filtering/filtering.md)
* **Назначение:** Встроенная в правую область панель фильтрации дерева документов по статусам, этапам пайплайна, смысловым типам, авторам загрузки и техническим форматам.
* **Файл:** `src/components/Filtering/filtering.md`

## 🛠 Руководство по интеграции и макетированию
* **Для дизайнера (Антон):** Все интерактивные макеты строятся с наследованием CSS-стилей текущего файла `index.css`. В макетах используются сетки и отступы, зафиксированные в описаниях компонентов.
* **Для разработчика (Руслан):** Файлы данных (State) строятся по JSON-схемам, задокументированным в каждом компоненте, для обеспечения бесшовного переключения с локальных Mock-данных на API-эндпоинты.
