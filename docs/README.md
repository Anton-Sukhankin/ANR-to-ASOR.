# Карта документации

Это общий индекс frontend-прототипа, а не отдельная спецификация. Начало работы и запуск описаны в [корневом README](../README.md). Для локальной задачи выберите один маршрут ниже; материалы встреч и всю документацию модулей читать заранее не требуется.

Явное решение пользователя может изменить требование; код подтверждает реализацию, но не заменяет такое решение.

## Источники и история

[Карта материалов встреч](../evidence/meetings/2026-08-24/evidence-map.md) хранит происхождение исходных требований. Она нужна для проверки конкретного решения, а не вместо актуальной спецификации. Последующие решения пользователя отражаются в соответствующем основном документе.

[Контрольный срез качества](../design-qa.md) фиксирует последнюю проверку документации, её ограничения и обоснование состава. Старые журналы QA и повторные снимки итераций выведены из проекта в восстановительный архив. В `evidence/meetings/` оставлены только кадры, непосредственно связанные с исходными требованиями; они не обязательный контекст каждой задачи и не предназначены для публикации.

## Синхронизация и проверки

После изменения интерфейса, данных или связи компонентов найдите основной документ по таблицам выше. Обновите изменившиеся факты и необходимые ссылки у потребителей. Если описанный контракт не изменился, зафиксируйте это в результате задачи с основанием проверки. План хранит прогресс и ссылки на требования; контрольный срез — основание и пределы последней проверки.

Для пакета комплектности используется [локальный workflow](../ai-completeness-module/docs/ui_docs_sync_workflow.md). Из корня проекта маршрут к документации дерева можно получить командой:

```sh
node ai-completeness-module/scripts/docs-sync-check.js src/components/FileTree/FileTree.js
```

Аргументы этой команды задаются относительно корня пакета комплектности. Скрипт выводит документы для проверки, но не доказывает соответствие текста коду. Для чата используются его приёмочные сценарии; для основного дровера — критерии спецификации и открытая приёмка чек-листа. Команды запуска и сборки находятся в корневом README; сборка не заменяет сценарную проверку.

После изменения документации проверьте локальные ссылки, пути реестра и согласованность статусов. Новый документ нужен только при отдельной ответственности, которую нельзя ясно разместить у существующего основного документа; добавляйте ссылку в ближайший индекс, не дублируя описание во всех индексах.
