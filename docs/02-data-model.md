# Контракт модели данных

Этот документ владеет демонстрационными сущностями, связями и потребителями данных трёх режимов. Он не является серверной схемой или гарантией полноты будущей интеграции. Правила интерфейса находятся в [спецификации проверки](07-check-workspace-target.md).

Прототип читает демонстрационные данные из [data/project-data.js](../data/project-data.js) через `window.SCOST_PROJECT_DATA`. JavaScript-обёртка поддерживает прямое подключение фикстур без локального `fetch`; в режиме Vite этот файл импортируется через [site-entry.js](../site-entry.js). Порядок запуска описан в [README](../README.md).

## Верхний уровень

- `project`: метаданные АСОР и задачи.
- `processingRun`: один запуск обработки АНР.
- `thresholdSettings`: пороги уверенности по типам сущностей.
- `sourceAnrRows`: исходные строки АНР до обработки.
- `asorRows`: плоский список строк таблицы АСОР.
- `matchDecisions`: решения ИИ по сопоставлению.
- `referenceCandidates`: альтернативы из справочников.
- `issues`: предупреждения и ошибки, отображаемые в таблице и дровере.
- `reviewActions`: решения пользователя во время проверки.
- `comments`: комментарии к проблемам или строкам.
- `processingLogEvents`: события журнала обработки.

## Основные сущности

### `sourceAnrRow`

Описывает исходную строку до обработки ИИ:

- `id`
- `rowNumber`
- `rawText`
- `group`
- `work`
- `material`
- `unit`
- `quantity`
- `price`
- `excelFields`

### `asorRow`

Описывает видимую строку таблицы АСОР:

- `id`
- `type`: `group`, `work` или `material`
- `parentId`
- `number`
- `name`
- `unit`
- `values`
- `sourceType`: `manual`, `imported`, `ai-generated` или `mixed`
- `sourceAnrRowId`
- `matchDecisionIds`
- `valueSources`

Приложение строит дерево из плоского массива `asorRows` по полю `parentId`.

### `matchDecision`

Описывает, как ИИ сопоставил исходные данные с АСОР или справочником:

- `id`
- `rowId`
- `sourceAnrRowId`
- `fieldKey`
- `entityType`
- `selectedValue`
- `confidence`
- `threshold`
- `algorithm`
- `steps`
- `candidateIds`
- `warningThresholdReason`

Массив `steps` хранит демонстрационное объяснение, а не исполняемый алгоритм: поиск в предыдущем АСОР, анализ соседних строк и сопоставление со справочником по триграммам.

### `referenceCandidate`

Описывает одну альтернативу из справочника:

- `id`
- `entityType`: группа, вид работ, материал, объем или цена
- `code`
- `name`
- `confidence`
- `reason`

### `issue`

Описывает предупреждение или ошибку:

- `id`
- `severity`
- `type`
- `rowId`
- `cellKey`
- `sourceAnrRowId`
- `matchDecisionId`
- `title`
- `description`
- `sourceValue`
- `selectedValue`
- `confidence`
- `alternatives`
- `reason`
- `recommendedAction`
- `status`
- `comments`

## Правила связей

- `asorRow.sourceAnrRowId` связывает строку АСОР с исходной строкой АНР.
- `asorRow.matchDecisionIds` связывает строку с решениями ИИ.
- `issue.rowId` связывает проблему с видимой строкой АСОР.
- `issue.sourceAnrRowId` связывает проблему с исходной строкой АНР.
- `issue.matchDecisionId` связывает проблему с решением ИИ, которое ее вызвало.
- `matchDecision.candidateIds` связывает решение со справочными альтернативами.
- `reviewAction.issueId` и `comment.issueId` связывают работу пользователя с предупреждением или ошибкой.
- `processingLogEvent.rowId` и `processingLogEvent.issueId` позволят в будущем переходить из журнала к строке или проблеме.

## Правило работы в прототипе

Прототип клонирует фикстуры в состояние страницы. Решения АНР, комментарии, статусы РД и редактирование объёма меняют локальные коллекции; исходный файл не перезаписывается. Серверного сохранения нет. Загрузка локального JSON комплектности не означает вызов API проверки.

## Значение ключевых полей и состояния

| Поле / группа | Смысл и ограничения | Потребитель |
|---|---|---|
| `id` | Устойчивый идентификатор сущности; не подменять индексом массива | Выбор, комментарии, связи, обновление элемента |
| `parentId` | Родитель строки АСОР; у корня нет родителя | Построение дерева и раскрытие пути |
| `number / rowNumber` | Отображаемый номер; не самостоятельный ключ связи | Таблица, карточки, маршруты |
| `sourceType` | Происхождение строки: `manual / imported / ai-generated / mixed` | Бейджи и фильтр «Всего создано» |
| `issue.severity / type` | Важность и характер проблемы; отсутствие `rowId` допустимо для нераспознанной строки АНР | Маркеры и фильтры АНР |
| `issue.status` | `open` — исходный незавершённый разбор; `confirmed / changed / resolved / sent-to-manual` считаются финальными в локальном фильтре | Активные проблемы и счётчики. Не все переходы имеют видимую кнопку |
| `confidence / threshold` | Демо-оценка и порог в шкале исходных данных; АНР использует доли, классификация файла отображает проценты | Объяснение сопоставления. Не унифицировать шкалы без адаптера |
| `selectedValue` | Предложение или выбранный результат проверки | Сравнение и черновик решения, не реальная запись сметы |
| `values / valueSources` | Значения ячеек и их происхождение | Таблица, пояснение источника |
| `reviewActions / comments` | Действия и комментарии с привязкой к проблеме | Локальный разбор; срок жизни — страница |
| `processingLogEvents` | Демонстрационные события процесса | Основа будущего журнала, не готовый журнал обработки |

## Потребители и маршруты чтения

Таблица читает `asorRows`; `issues` определяют индикацию проблемных ячеек и состав разбора АНР. Интерактивные маркеры сейчас не выводятся — см. [GAP-ANR-01](04-ui-rules.md#table-entry-limits). Список АНР собирается из проблем и автоматически созданных строк. Детальный разбор следует цепочке `issue → sourceAnrRow → matchDecision → referenceCandidates`. Выбор альтернативы не меняет данные до подтверждения. Комментарий и действие проверки остаются привязаны к своей сущности.

## Комплектность

Текущая резервная фикстура находится в `checks.completeness`:

| Поле | Содержание |
|---|---|
| `summary` | Исходные демонстрационные счётчики; после загрузки дерева используются производные значения |
| `requirements[]` | `id, kind, group, title, result, status, linkedFileId?` |
| `requirements[].kind` | `required-document` либо `special-condition`; определяет одну из двух категорий |
| `requirements[].status` | `completed / not-completed / processing / error` |
| `files[]` | Иерархия `id, kind, name, status, declaredType, detectedType, downloadable, comment?, children?` |
| `linkedFileId` | Связь с файлом, когда она существует; нельзя выводить неработающую ссылку при отсутствии цели |

Основной путь также загружает [дерево модуля](../ai-completeness-module/src/components/FileTree/mockTreeData.json). Его поля и стадии описаны в [контракте дерева](../ai-completeness-module/src/components/FileTree/file_tree_and_pipelines.md); адаптация в `app.js` не меняет JSON в исходной папке. При недоступности загрузки остаются резервные данные. Нельзя считать схему резервного `files` побайтово одинаковой со схемой модуля.

Статус итога выводится локально: явный флаг повторной проверки даёт обработку; проблемы и невыполненные требования — неподтверждённость; при отсутствии проблем незавершённая обработка даёт промежуточное состояние; иначе итог подтверждён. Это демонстрационная агрегация, не правило реальной экспертизы.

## Изменения РД

`checks.rdChanges.changes[]` содержит:

| Поля | Смысл и ограничения |
|---|---|
| `id / rowId` | Ключ изменения и ссылка на существующую строку АСОР |
| `rowNumber / name / svLevel` | Текст карточки и нейтральный атрибут `SV 0/1/2` |
| `previousVolume / proposedVolume` | Отображаемые объёмы; редактирование меняет только предложенный объём |
| `reviewState` | `warning` требует решения; `auto-applied` — обработано автоматически; `applied / cancelled` — принятые решения. Редактирование объёма само по себе не меняет этот статус |
| `warningReason` | Объяснение неоднозначности из данных, не результат вычисления правил в браузере |
| `similarRows[]` | `rowId, rowNumber, name, svLevel, currentVolume, similarityPercent, unit?`; проценты фиктивные |

Похожие строки проверяются по `rowId`: исключаются текущая строка, дубли и отсутствующие цели. Маршрут родителей строится по фактическому дереву АСОР. Просмотр похожей строки не меняет цель применения. Локальные комментарии РД привязаны к идентификатору изменения, не к АНР-проблеме с похожим номером.

## Граница изменения контракта

При изменении поля проверить источник, преобразование в `app.js` и реальные потребители выше. Для серверного формата отдельно определить обязательность полей, ошибки, права, сохранение и миграцию состояния. Пример фикстуры не устанавливает эти правила автоматически.
